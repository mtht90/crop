# Chat

白 × 青で統一したリアルタイムチャット。ルームを作ってQRで招待し、メッセージ・写真・音声・ビデオ通話ができます。
Node.js + WebSocket（`ws`）で、ビルド工程はありません。

## 機能

**トーク**
- テキスト / 写真（自動で縮小）/ 音声メッセージ（最長2分）
- 返信、リアクション、@メンション、リンクのプレビュー
- 編集、送信取消、既読表示（「既読 n」）、入力中表示
- 過去ログの読み込み（上にスクロール、1ルーム2000件まで保存）、メッセージ検索

**ポイントとショップ**
- メッセージを送ると、文字数ぶんポイントがたまる（空白は除く・1通あたり最大100）
- ショップでフリーフォント（Google Fonts の Open Font License フォント16種）をポイントで購入し、自分のメッセージのフォントにできる（みんなの画面に反映）

**アイコン**
- 自分のアイコンを画像で設定（位置と大きさを調整して256pxで保存）
- ルームのアイコンは管理者だけが変更できる

**メッセージの長押しメニュー**
- スマホは長押し、PCは右クリック（またはホバー時の絵文字ボタン）で、吹き出しが浮き上がってメニューが開く
- 返信 / コピー / 編集 / 送信取消、管理者は他の人のメッセージも削除できる
- 管理者はルームごとに「メンバーのメッセージ編集」「メンバーの送信取消」を禁止できる

**ルーム**
- 公開ルーム（「さがす」に表示）/ 招待制ルーム（推測されにくいURL）/ 合言葉つき
- QR招待（合言葉ごとQRに含めることも可能）と、アプリ内のQR読み取り（カメラ / 画像から）
- 1対1のDM、メンバー一覧
- 管理機能：作成者による管理者の任命、退出させる・追放（再参加禁止）、メッセージ削除、ブロック

**通話**
- 音声 / ビデオ通話（最大4人程度を想定、端末同士を直接接続）
- ミュート、カメラのオン/オフ・切り替え、話している人の強調表示、最小化

**そのほか**
- プッシュ通知（閉じていても届く。ルームごとにオフ可、メンションはオフでも届く）
- アプリを開いている間はプッシュの代わりに、画面上部にアプリ内バナーが出る（タップでそのトークへ、上にスワイプで消える）
- ホーム画面に追加してアプリとして使える（iPhone は追加したアプリでのみ通知が届きます）
- 別の端末への引き継ぎ（10分間有効のQR / コード。新しい端末のアプリ内でQRを読み取れます）
- ライト / ダーク / 自動の表示切替

## ローカルで動かす

```bash
cd chat
npm install
npm start
```

`http://localhost:3000` を開きます。`REDIS_URL` がないときは `chat/data/` に保存します。

## Render へのデプロイと自動更新

リポジトリ直下の `render.yaml`（Blueprint）で次の2つが作られます。

| サービス | 内容 |
|---|---|
| `chat`（Web Service, free） | アプリ本体。URL は `https://chat.onrender.com`（名前が空いていれば） |
| `inachat-store`（Key Value, free） | ルーム・履歴・写真や音声・通知登録の保存先 |

1. Render ダッシュボードで **New → Blueprint** を選び、このリポジトリとブランチを指定して **Apply**
2. 以後はそのブランチに push するたびに Render が自動で再デプロイします（Auto-Deploy は既定でオン）。`render.yaml` の変更も自動で反映されます

### URL の引っ越し（inachat → chat）

Render の公開 URL はサービス作成時に決まり、あとから変えられません。そこで新しい `chat` サービスを作り、保存先は元の `inachat-store` を共有しています。

- `chat` サービス（`CANONICAL=1`）は起動時に自分の URL を保存先に書き込みます
- 元の `inachat` サービスはそれを検知すると保存先への書き込みを止め、開いた人をアカウントごと新しい URL へ転送します
- 通知用の鍵も保存先で共有するため、登録済みの通知はそのまま届きます

旧 `inachat` サービスは転送役として、しばらく残しておいてください（消すと旧 URL のブックマークが使えなくなります）。

## 無料プランの注意

- Web サービスは15分アクセスがないとスリープし、次のアクセスで起動に30秒〜1分かかります
- 無料の Key Value は容量が小さく、Render 側の都合でまれに再起動されると保存内容が消えます。写真と音声は合計 12MB を超えると古いものから消えます（`MEDIA_BUDGET_MB` で変更可）
- しっかり残したい場合は、Key Value を有料プランにするか、`REDIS_URL` を永続化つきの Redis（Upstash など）に向けてください
- 通話は端末同士の直接接続です。携帯回線どうしなどでつながらない場合は TURN サーバーを設定してください（下記）

## 環境変数

| 変数 | 説明 |
|---|---|
| `REDIS_URL` | 保存先の Redis / Key Value。未設定ならファイル保存 |
| `SECRET` | 通知（VAPID）鍵の元になる値。変えると各端末で開き直したときに通知が再登録されます |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | 鍵を直接指定したい場合（`SECRET` より優先） |
| `VAPID_SUBJECT` | 通知サービスに伝える連絡先（`mailto:` か URL）。未設定なら Render の公開URL |
| `CANONICAL` | `1` にしたサービスが正式な URL になり、同じ保存先を使う他のサービスは訪問者をそこへ転送します |
| `MEDIA_BUDGET_MB` | 写真・音声の保存上限（MB）。既定は Redis 利用時 12、ファイル保存時 500 |
| `TURN_URLS` / `TURN_USERNAME` / `TURN_CREDENTIAL` | 通話用 TURN サーバー（`TURN_URLS` はカンマ区切り） |
