# 建築ゲーム 実装仕様書（Godot 4 / PC・Steam）

戦闘のない建築特化のサンドボックス。壮大な建築を建て、シェーダーを効かせて写真を撮ることが目的。買い切り、ソロ、一人称。

## 1. 空間モデル

### 1.1 セルと枠

世界を一辺 2.5m の立方体セルで区切る。セル座標は整数 `Vector3i`。

1セルが持つ設置枠は6つ。

| 枠 | 内容 |
|---|---|
| `WALL_PX` / `WALL_NX` / `WALL_PZ` / `WALL_NZ` | 側面4枚 |
| `FLOOR` | 下面 |
| `DIAG` | セル内部を占める斜め要素（階段・屋根） |

天井は「上のセルの FLOOR」が兼ねる。1枠に置けるパーツは1つだけ。この制約により、どれだけ複雑に建てても構造が破綻しない。

### 1.2 壁の所有権を正規化する

セル A と B の境界にある壁は、両方から参照できてしまう。**必ず +X 側・+Z 側の枠だけを実体とする**。

```gdscript
# (cell, face) を正規化して一意にする
func canonical_wall(cell: Vector3i, face: int) -> Array:
    match face:
        FACE_NX: return [cell + Vector3i(-1, 0, 0), FACE_PX]
        FACE_NZ: return [cell + Vector3i(0, 0, -1), FACE_PZ]
        _:       return [cell, face]
```

これを怠ると「同じ壁が二重に存在する」バグが必ず出る。最初に入れること。

### 1.3 パーツのデータ

1パーツは 64bit に収める。数十万パーツを扱うため、辞書にオブジェクトを詰めるのは避ける。

| フィールド | ビット | 内容 |
|---|---|---|
| `type` | 4 | WALL / FLOOR / STAIR / ROOF / 拡張形状 |
| `recipe` | 12 | レシピID（形状バリエーション） |
| `material` | 12 | 素材ID |
| `rotation` | 2 | 0〜3（90度単位） |
| `edit_mask` | 16 | 編集で残っている格子（後述） |
| `flags` | 8 | 下書き / ミラー生成 / ロック 等 |

保持は `PackedInt64Array` またはチャンクごとの `Dictionary[Vector3i → int]`。スパースに持つ。

## 2. 配置

### 2.1 向きの自動決定

プレイヤーに回転を意識させない。カメラの向きと注視点から、置くべき枠と向きを決める。

1. カメラから前方へレイキャスト（最大 20m）
2. 当たった面、または一定距離の空中点から、対象セルを求める
3. 選択中のパーツ種に応じて枠を決める
   - 壁：対象セルの、プレイヤーに最も近い側面
   - 床：対象セルの FLOOR
   - 階段・屋根：対象セルの DIAG。向きはカメラの向いている方位（4方位に量子化）
4. 手動回転（`R`）で向きを1段ずつ上書きできる

### 2.2 吸着

既存パーツの面・辺に対して自動でそろえる。地形がないので、地面は y=0 平面として扱う。

- 床の縁 → 壁が自動でその縁に乗る
- 壁の上端 → 床が次の階の高さに乗る
- 隣接する壁 → 面がそろう

### 2.3 支持は不要

浮いた場所にも置ける。物理的な整合性より自由度を優先する。ただし補助として**支柱の自動生成**を用意する。選択した床から真下へ、地面または最初の障害まで柱を生やす。

### 2.4 連続設置

左ボタンを押したままカーソルを動かすと、通過した枠へ次々に置く。同一フレームでの重複設置を防ぐため、直前に置いた枠を記憶しておく。

## 3. 編集（フォトナ方式）

### 3.1 基本

パーツを見て編集キー（既定 `G`）を押すと、そのパーツの面が 3×3 の格子に分割されて表示される。

1. 押しながらドラッグで、抜きたいマスをなぞって選択
2. ボタンを離すと確定。選択されたマスが開口になる
3. 確定前に右クリックでキャンセル

`edit_mask` は 9bit（3×3）。ビットが立っているマスが**残っている**部分。初期値は `0b111111111`。

床・階段・屋根も同じく 3×3 で編集できる。床を抜けば吹き抜け、階段を抜けば踊り場になる。

### 3.2 建築特化として足す機能

編集の操作自体は変えない。外側だけ拡張する。

- **形状の保存**：確定した `edit_mask` に名前を付けて登録。以降はスロットから1操作で同じ開口を作る
- **スポイト**（既定 `Alt+左クリック`）：狙ったパーツの type / recipe / material / rotation / edit_mask をまとめて手元にコピー
- **一括適用**：範囲選択した壁すべてに、同じ `edit_mask` を適用
- **編集の解除**：`edit_mask` を初期値へ戻す

長い壁面に等間隔で窓を開ける作業がここで完結する。この3つは初期実装に含めること。

### 3.3 メッシュ生成とキャッシュ

`edit_mask` は 512 通り。パーツ種ごとに、マスクからメッシュを生成して**キャッシュする**。

```gdscript
var _mesh_cache := {}   # key: [type, recipe, edit_mask] → ArrayMesh

func get_mesh(type: int, recipe: int, mask: int) -> ArrayMesh:
    var key := [type, recipe, mask]
    if not _mesh_cache.has(key):
        _mesh_cache[key] = _build_mesh(type, recipe, mask)
    return _mesh_cache[key]
```

毎回生成すると編集のたびに固まる。必ずキャッシュを挟む。

## 4. 素材

### 4.1 形状と素材の分離

`material` は `type` / `recipe` と独立。建て直さずに雰囲気だけ変えられる。レシピ100種の多くはこの素材レイヤーに属する。

### 4.2 キー切り替え

数字キー `1`〜`8` にスロットを割り当てる。押した状態で設置すれば、その素材で建つ。

- ホイールで前後のスロットへ送る
- `Tab` 長押しで円形メニューを開き、100種から任意のものをスロットへ登録
- スロット構成はプロファイルに保存

### 4.3 塗り替え

設置済みパーツの素材だけを差し替えるモード（既定 `B`）。狙って左クリックで1枚、範囲選択で一括。

### 4.4 レシピ100種の内訳（目安）

| 分類 | 数 | 内容 |
|---|---|---|
| 素材 | 40 | コンクリート、木、トタン、タイル、土壁、ガラス。汚れ・経年違いを含む |
| 構造 | 20 | 斜め壁、曲面、アーチ、柱、梁、手すり、階段の形違い |
| 開口の型 | 15 | 窓、扉、格子、欄間、シャッター |
| 装飾 | 15 | 室外機、配管、看板、電線、雨樋、自販機 |
| 屋根 | 10 | 瓦、波板、陸屋根、庇 |

**装飾15種の優先度が最も高い。** 室外機・配管・電線があるだけで、同じ箱が日本の風景に変わる。目指す画作りに直結するので、ここは削らない。

## 5. 削除（確定）

マウス操作で対象を特定する方針とし、以下3系統を用意する。

| 操作 | 動作 |
|---|---|
| 右クリック | 照準しているパーツを1つ削除。押しっぱなしで連続削除 |
| `Shift` + 右ドラッグ | 範囲を箱で囲み、離すと内部を一括削除 |
| `Ctrl` + 右クリック | 同一素材・同一種の連結部分をまとめて削除（塗りつぶし削除） |

削除対象は常に半透明の赤でハイライトする。誤削除の防止として、削除も通常の履歴に積む。

## 6. カメラと移動

| モード | 内容 |
|---|---|
| 徒歩（一人称） | 完成後に歩いて見る。重力あり |
| 建築（自由飛行） | 重力なし。WASD＋QE で上下。`Shift` で加速 |
| 俯瞰 | 選択した建物を中心に回り込むオービット。ホイールで距離 |

建築中は自由飛行が既定。`F` で徒歩と飛行を切り替え、`Tab` 一押しで俯瞰へ。

俯瞰は「視点を引く」だけでなく**注視点を建物中心に固定して回り込める**ことが重要。全体のシルエットを確認する用途で、これがないと壮大な建築は作れない。

地点ブックマーク（`Ctrl+1〜4` で登録、`1〜4` 長押しでワープ）も用意する。

## 7. 建築支援機能

優先度順。上4つは初期実装に含める。

1. **ミラー**：軸を1本置くと、以降の設置が反対側にも自動生成される。軸は2本まで（十字対称）
2. **ブループリント**：範囲選択した一角を名前付きで保存し、回転して別の場所へ配置
3. **下書きモード**：実体のない半透明の骨組みを置き、形が決まってから一括で実体化
4. **断面表示**：指定した高さから上を非表示にする。内装作業用
5. 配列複製：間隔と個数を指定してパーツを並べる
6. 高さロック：同じ階の高さに置き続ける
7. 測定ツール：2点間の距離と、囲んだ面積
8. リファレンス画像：空中に画像板を貼る

### 履歴

- アンドゥ／リドゥは**無制限**（メモリ上限まで）
- 履歴スライダーで任意の時点まで一気に戻れる
- 1操作＝1エントリ。連続設置は「押してから離すまで」を1エントリにまとめる

## 8. ワールド

### 8.1 チャンク

- チャンクは 16×16×16 セル（＝40m 立方）
- 空のチャンクは存在させない。パーツが置かれた時点で生成
- プレイヤー周囲の一定範囲のみメモリに保持し、外れたチャンクは書き出して解放

### 8.2 原点シフト

無限に遠くへ行くと float の精度が落ち、描画が震える。

**プレイヤーが原点から 4km を超えたら、ワールド全体の座標を平行移動して原点を戻す。** セル座標は整数なので論理側は無傷。描画ノードの `global_position` だけを補正する。この仕組みは後付けが難しいので、最初から入れておくこと。

### 8.3 地面

地形はない。y=0 に無限平面を1枚。遠景はフォグで落とす。

## 9. セーブ

### 9.1 形式（確定）

- チャンク単位で、**変更のあったチャンクだけ**書き出す
- 各チャンクは「枠座標 → 64bit パーツ」のスパースな配列
- 座標順にソートして差分エンコード後、`FileAccess.COMPRESSION_ZSTD` で圧縮したバイナリ
- ワールドは1フォルダ。`world.meta`（版数・原点シフト量・スロット情報）＋ `chunks/<x>_<y>_<z>.bin`

### 9.2 運用

- 自動保存：60秒ごと、および変更があったチャンクのみ
- 手動スロット：任意の数。スロットはチャンクフォルダのスナップショット（ハードリンクまたはコピー）
- ブループリントは別形式（`.bp`）で単体書き出し。将来の共有に使える

### 9.3 版数

先頭に必ずフォーマット版数を書く。パーツのビット構成を変えたら版数を上げ、読み込み時に変換する。ひとり開発でも、これがないと自分の過去データを壊す。

## 10. 撮影モード

`P` で入る。UIは全消し。

- 自由カメラ（建築中の飛行と同じ操作）
- 焦点距離（12〜200mm）
- 被写界深度：合焦距離、絞り。クリックした位置に合焦するピント合わせ
- 天候：晴れ・曇り・雨・霧。強度スライダー
- 時刻：0〜24時のスライダー。太陽と空の色が連動
- 構図補助：三分割線、水平線
- 保存：PNG。解像度はゲーム画面の1〜4倍から選択

**建築中の照明とは完全に分離する。** 建築中は常に明るい固定光、撮影モードでのみ時刻と天候が効く。作業が暗さで止まらないようにするため。

## 11. ユーザーシェーダー

### 11.1 仕組み

外部注入（ReShade等）に依存しない。ゲーム側にポストプロセスの枠を持つ。

- ユーザーは `user://shaders/` に `.gdshader` を置く
- ゲーム内の管理画面で、有効・無効、適用順、公開パラメータを操作
- 起動時とフォルダ変更時に読み直す

### 11.2 渡す変数の契約

**この契約を最初に確定し、文書として同梱すること。** 後から変えると既存のシェーダーが全部壊れる。

| uniform | 型 | 内容 |
|---|---|---|
| `screen_texture` | sampler2D | 直前の描画結果 |
| `depth_texture` | sampler2D | 深度 |
| `normal_texture` | sampler2D | ワールド法線 |
| `time_of_day` | float | 0.0〜1.0 |
| `camera_fov` | float | 度 |
| `weather` | vec4 | 雨量・霧濃度・風・予備 |

`// @param 名前 min max default` 形式のコメントを解析して、管理画面にスライダーを自動生成する。

### 11.3 安全性

シェーダーはコード実行に近い。読み込み失敗時にクラッシュせず、その1枚だけ無効化してログに残すこと。

## 12. 描画の最適化

セル 2.5m は小さい。10階建てのビルで数千パーツになるため、素朴に `MeshInstance3D` を並べると即座に破綻する。

- チャンクごと、`(mesh_key, material)` ごとに `MultiMeshInstance3D` へまとめる
- `mesh_key` は `[type, recipe, edit_mask]`。同一形状は1つのメッシュを共有する
- パーツの追加・削除では、そのチャンクの該当 MultiMesh のみ再構築（全体を作り直さない）
- 遠景のチャンクは簡易メッシュへ差し替える（LOD）。編集の穴は描かない
- 屋内の見えない面は当面カリングしない。まず動くものを作り、計測してから対処する

**先に計測すること。** 1000パーツ、10000パーツ、100000パーツで fps を測るベンチシーンを最初に作る。

## 14. 実装順

ひとり開発なので、順番を守ることが最大の防御になる。

**第1段階：操作感だけを作る（これが最優先）**

壁と床のみ、素材1種、固定サイズの平地、編集なし、保存なし。自由飛行と設置・削除だけ。**これを1週間自分で触って、面白いかを判断する。** ここが駄目なら、レシピ100種を作る意味はない。

**第2段階：建築の核**

階段・屋根、編集（3×3）とキャッシュ、素材レイヤーとキー切替、アンドゥ、セーブ。

**第3段階：建築支援**

ミラー、ブループリント、下書き、断面、俯瞰オービット。ここまでで「創作ツール」になる。

**第4段階：規模**

チャンク化、原点シフト、MultiMesh 最適化、LOD。第1〜3段階は 1km 四方の固定ワールドで進めてよい。ただしセル座標を整数で持つ設計だけは最初から守ること。

**第5段階：見せる**

撮影モード、シェーダー管理、レシピの拡充。

### レシピは20種から始める

100種を最初から作ると、他が何も進まない。装飾と素材を優先して20種で通し、構造が固まってから足す。「完成させてから出す」方針なら、なおのこと完成の定義を自分で締められる状態にしておくこと。
