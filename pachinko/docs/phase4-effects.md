# Phase 4: 演出システム(ロジック層)

**スコープの明示**: このコミットで実装したのは3.4節が要求する演出システムのうち
**「演出テーブル」「演出選択ロジック」「保留色(先読み)判定」「デバッグ表示」**の部分のみ。
実際のカットイン映像・アニメーション・UIレイアウト・サウンド同期といった**視覚/聴覚アセットを
伴う実装は、Godotエディタでシーンを組み立てながら作る必要があり、この開発環境
(エディタ本体なし)では正しく検証できないため、意図的にスコープ外にしている**。

## 実装した2段階抽選の徹底

Phase 3で確定した`LotteryResult`を受け取ってから演出を選ぶ、という順序をここでも厳密に守った。

- `EffectDef`/`EffectTable`: リーチ演出・カットイン等、1回の変動全体を代表する演出候補。
  当たり時重み(`weight_win`)とハズレ時重み(`weight_lose`)を独立して持つ。
  `weight_lose = 0` にした演出(`premium_fugaku_awakening`)は構造的に大当たり時にしか
  選ばれない=**信頼度100%のプレミア演出**になる(3.4節の必須要件)。
- `HoldColorRule`/`HoldColorTable`: 保留色(白/青/緑/赤/金/虹)も同じ当落分離テーブル方式。
  虹は`weight_lose = 0`にしており、出た時点で当確級として扱える。
- `EffectSelector`/`HoldColorSelector`はいずれも「確定済み`LotteryResult`を受け取って
  選ぶだけ」の一方向データフローで、演出側から抽選結果を書き換える経路は存在しない。

## RNGストリームの分離

`LotterySystem`(内部抽選)・`HoldColorSelector`(保留色)・`EffectSelector`(演出)は
それぞれ独立した`RandomNumberGenerator`を持つ。`GameManager.lottery_seed`を固定すると
3つとも(`seed`, `seed+1`, `seed+2`)決定的になり、3.2節が求める「シード値固定でテスト可能」
を満たす。

## デバッグ表示(3.4節の要件を反映)

`GameManager`のデバッグラベルに以下を常時表示するようにした:

```
発射数: n  入賞数: n  保留: k/4 [赤(戦闘配置警告), 白(通常監視), ...]
状態: 確変中  獲得出玉: n
直近結果: 大当たり!/ハズレ
選択演出: SPリーチ: 僚機参戦カットイン (信頼度42.9%)
```

「内部抽選結果」(直近結果)と「選ばれた演出」(選択演出、信頼度%付き)を並べて表示しており、
3.4節の「デバッグモードで内部抽選結果と選ばれた演出を並べて表示」を満たす。

## この段階で未実装(次にやるべきこと)

以下は視覚/聴覚アセットの制作、またはGodotエディタでのシーン構築が前提のため
意図的に見送っている。**「実機確認ができないから」ではなく「素材制作とエディタ作業そのもの
が必要だから」の見送りである点に注意**(誤魔化しではなく明示的なスコープ判断):

1. **保留アイコンのUI表示**: `HoldColor`を実際にCanvasLayer上のアイコン(色付き警告灯風
   スプライト)として盤面に表示する。`GameManager._hold_colors_text()`が持つ情報を
   `TextureRect`等に流し込むだけなので、ロジックとしては既に用意済み。
2. **ゾーン演出/リーチ/SPリーチ/カットインの実映像**: `AnimationPlayer`/`Tween`を使った
   実際の画面演出。オリジナルイラスト・カットイン素材が必要。
3. **保留の「変動中格上げ」**: 現状は入賞時点の色のみ決定している(Phase -1リサーチが
   指摘した2パターンのうち1つ目のみ対応)。変動中に確率的に色を格上げする処理は
   `HoldColorSelector`に`try_upgrade(current_color, result) -> HoldColor.Color`的な
   メソッドを追加する形で拡張可能。
4. **ゾーン演出の持続処理**: `alert_zone`演出が選ばれた場合、「該当保留が消化されるまで
   効果を持続」させるステート管理(3.4節要件)は未実装。
5. **ステージ/背景の状態遷移**: 通常/時短/確変でのステージ切り替えは`GameState.mode_changed`
   シグナルに購読するだけで実装できる土台はあるが、実際の背景/BGM切り替え本体は未実装。
6. **変動時間の可変化**: `SpinController.spin_duration_sec`を、選ばれた`EffectDef`の
   カテゴリ(通常/ゾーン/ノーマルリーチ/SPリーチ)に応じて可変にする(Phase3のTODOと同じ)。

## 実質信頼度の検証(設計時点での参考値)

`default_hold_color_table.tres`の重みから算出される実質信頼度(白〜虹):

| 色 | 信頼度 |
|---|---|
| 白 | 約2.4% |
| 青 | 約7.7% |
| 緑 | 約25.0% |
| 赤 | 約55.6% |
| 金 | 約87.0% |
| 虹 | 100%(プレミア相当) |

`default_effect_table.tres`のプレミア演出(`premium_fugaku_awakening`)は`weight_lose=0`
のため常に信頼度100%になる。いずれも3.2節同様「仮パラメータ、後で調整可能」。
