# SLOT — Three.js パチスロ実機シミュレーター

ブラウザでパチスロ実機を再現した 3D ゲームです。
抽選は「内部抽選 → 引き込み制御」の 2 段で、レバー ON の瞬間に役が決まり、ストップボタンを押したタイミングから最大 4 コマの範囲で出目が決まります。
ジャグラー型の A タイプに、上部液晶の予告演出を足した台です。ボーナスを引くと液晶全体が「LUCKY!!」で光ります (独立した告知ランプはありません)。
所持金 3 万円を持って台に座り、千円ずつメダルを借りて打ち、換金して帰るまでが 1 日です。

## 起動

ES Modules と fetch を使うため、ローカル HTTP サーバー経由で開いてください (`file://` では動きません)。

```bash
cd slot
python3 -m http.server 8000      # もしくは: npx serve .
# → http://localhost:8000/
```

| URL ハッシュ | 効果 |
|---|---|
| `#debug` | 起動時にチューニングパネル (lil-gui) を開く。`G` キーや ⚙ ボタンでも開閉できる |
| `#lite` | 背景ホールと隣台を省き、ピクセル比を 1 に固定する (低スペック端末向け) |
| `#zoom` | カメラをリール寄りにする |

組み合わせるときは `#debug-lite` のようにハイフンでつなぎます。

ビルド工程も外部 CDN も使いません。依存物はすべて `assets/` に同梱しています。

## 操作

| 操作 | キーボード | マウス / タッチ (筐体を直接操作) |
|---|---|---|
| MAX BET | `B` / `Shift` | デッキ左の黄色い MAX BET ボタン (ベット待ちのあいだ光る。ベット前にレバーを叩くと点滅して催促) |
| レバー | `Space` / `Enter` / `↑` | 赤いレバー玉をタップ、または下へ引く (デッキ左側一帯が判定) |
| 停止 (左・中・右) | `←` `↓` `→` / `1` `2` `3` / `Z` `X` `C` | ストップボタン (その下の配当表あたりまで判定あり) |
| 千円入れる (46 枚) | `M` | 右の千円入れ機のボタン、または画面左上の「千円入れる」 |
| 換金して終了 | — | 画面右上の「換金」 |

iPhone は Safari の仕組み上 `navigator.vibrate` が使えないため、ios-haptics の方式で、筐体をタップした瞬間だけ本体を振動させます。
告知の「ブイーン」という長い振動は Android Chrome などの `navigator.vibrate` 対応端末で動きます。iOS では音・画面の揺れ・光で表現します。

- 実機どおり、MAX BET を押してからでないとレバーは効きません。リプレイ成立時だけ自動でベットされます (`CONFIG.play.autoBet` を true にすると毎ゲーム自動ベット)。
- メダルが 3 枚未満になったら千円を入れてください (自動では借りません)。
- 1 ゲームは最短 4.1 秒です (実機と同じウェイト)。
- 所持金・持ちメダル・過去の戦績は localStorage に保存されます。

## お金と 1 日の流れ

| 項目 | 値 (`CONFIG.money`) |
|---|---|
| 1 日の所持金 | 30,000 円 |
| 貸しメダル | 1,000 円で 46 枚 |
| 換金 | 1 枚 20 円 (等価ではないので、出した分をそのまま流すと少し目減りする) |

台の設定 (1〜6) は日ごとに隠れて決まり (`CONFIG.settingOdds`。実際のホールに近く、設定 1 が 6 割・設定 4 以上は 14%)、換金したときに答え合わせとして表示されます。
換金すると、投資・換金額・収支・回転数・BIG/REG・設定と通算収支が出て、次の日に進みます。
筐体上のデータカウンターに BIG / REG / 現在の回転数 / 総回転数とスランプグラフが出るので、それを見て粘るか帰るかを決めます。

## 告知と液晶の予告

| 演出 | 意味 |
|---|---|
| 先ペカ (レバー ON で液晶が LUCKY!! に) | ボーナス確定。全体の約 25% |
| 後ペカ (第 3 停止ボタンを離した瞬間に LUCKY!!) | ボーナス確定。約 75% |
| プレミアム (LUCKY!! が虹色) | ボーナス確定。告知の 1/8 |

LUCKY!! は 7 を揃えるまで点きっぱなしです。点灯の直前に一瞬だけ音が消え、「ペカッ」→ 低い「ブイーン」と振動、光の波紋が続きます。

後ペカのゲーム (約 6 割) と、はずれゲームのごく一部 (約 5%、チェリー成立時は 20%) では、レバー ON から液晶で予告が始まり、停止ごとに昇格して、第 3 停止ボタンを離した瞬間に決着します。

| 予告 | 停止ごとの変化 | 期待度の目安 (`CONFIG.yokoku.types`) |
|---|---|---|
| ジャグリング加速 | 玉が増えて速くなる | 低 |
| ピエロ顔アップ | ピエロが迫ってくる (! → !! → !!!) | 中 |
| カットイン | 帯の色が 青 → 緑 → 赤 → 金「激アツ!!」→ 虹 へ昇格 | 色しだい (虹ははずれなし) |
| 7 飛来 | 7 が 1 つずつ落ちてくる。3 つ並べば当たり | 高 |
| 暗転 | 筐体ごと消灯して心音 | 激アツ |

### 小役・ボーナス・連チャンの演出

| 場面 | 演出 |
|---|---|
| ぶどう / リプレイ | 液晶の隅にぶどう「+10」/「REPLAY」 |
| チェリー | 帯で「チャンス!?」。チェリーはボーナスと重複することがある (重複時は後ペカが多い) |
| ベル / ピエロ (各 1/1092) | 「レア役!!」でリールがストロボし、ギュイン音と振動 |
| ボーナス中 | 獲得枚数とゲージ、連チャン数のバッジ |
| ボーナス終了 | 獲得枚数と、連チャン中なら合計枚数 |
| 連チャンゾーン (ボーナス後 100G) | 液晶が夜のステージになり、残り G 数と「○連中」を表示。残り 10G で赤く点滅 |

スペシャル BGM (実機のジャグラーのスペシャルボーナス音と同じ条件):

| 条件 | BGM |
|---|---|
| ボーナス後 3G 以内に BIG (実機では「軍艦マーチ」) | `sp1` |
| ボーナス後 100G 以内のゾロ目 G (11・22・…・99G) で BIG | `sp2` |
| プレミアム告知 (虹) からの BIG | `premium` |

実機のジャグラーに確変はありません。連チャンゾーンは「100G 以内に引き戻せば連チャン」を数えて見せるだけで、確率は変わりません。
`CONFIG.chain.boost` を 1 より大きくすると、ゾーン中だけボーナス確率がその倍率になります (確変風)。

筐体上のデータカウンターには BIG / REG / 現在の回転数 (500G 以上で赤) に加えて、合算確率・ぶどうの回数と確率・チェリー確率・最大ハマりが出ます。実機のホールと同じく、ぶどう確率と REG 確率から設定を推測できます。
隣の台も同じくらいの確率でときどき当たります (`#lite` 以外)。隣の台は自台と連動せず、それぞれ自分のペースでオートプレイします (`src/neighbors.js`)。台の間隔は `CONFIG.render.neighborGap`、スマホ縦画面での映り方は `CONFIG.render.portraitHalfW` で変えられます。画面の外の隣台が当たっているときは、その側の画面端がピンクに光ります。



通常時はゲーセンらしいチップチューン (スロットは congusbongus「Head in the Sand」、パチンコは lordzintick「The Arplands」) を小さめに流します (`CONFIG.audio.normalBgm`)。実機のジャグラーは通常時は無音です。

フォントは、左上の所持金表示が Orbitron + Zen Kaku Gothic New、それ以外 (液晶・筐体・ボタン・換金画面) が Dela Gothic One、数字の一部が DSEG7 です。

ボーナス中は液晶に獲得枚数とゲージが出て、終了時に獲得枚数を表示します。
目押しアシスト (`CONFIG.play.assistAlignAfterNotice`) がオンなら、告知後のゲームで 7 が自動で揃います。
BIG は 360 枚超、REG は 112 枚超の払い出しで終了します。

## パチンコ (切り替え式)

画面右上の「パチンコ」ボタン (または `Tab`) で、暗転してパチンコの島へ移ります。所持金と投資は共通で、換金するとメダルと玉をまとめて精算します。
構想メモは `docs/pachinko-concept.md`。

| 項目 | 内容 (`src/pachinko/config.js`) |
|---|---|
| スペック | ライトミドル。通常 1/199.8、ST 100 回 (1/79.9・継続率 約 72%) |
| 振り分け | ヘソ: 4R 確変 (ST へ) 50% / 4R 通常 (時短 100 回) 50%。電チュー: 10R 40% / 4R 60% (すべて ST) |
| お金 | 1000 円 = 250 玉。換金は 1 玉 3.57 円 (28 玉交換) |
| 賞球 | ヘソ 3 / 電チュー 1 / アタッカー 15 / 一般入賞 3。1 ラウンド 10 カウント |

| 操作 | キーボード | マウス / タッチ |
|---|---|---|
| 発射 ON/OFF | `Space` | 右下のハンドルをタップ |
| 強さ | `↑` `↓` (`←` 左打ち / `→` 右打ち) | ハンドルを上下になぞる |
| PUSH | `P` | 上皿の赤いボタン (SPSP リーチで点滅) |
| 千円 | `M` | 上皿左の緑のボタン、または左上の「千円入れる」 |

- 玉は盤面上の 2D 物理で動きます (`src/pachinko/physics.js`)。釘・風車・ステージ・ヘソ・電チュー・ゲート・アタッカー・一般入賞口があり、強さ 0.4〜0.6 で左打ち、0.9 以上で右打ちになります。
- 左打ちのヘソ入賞は千円あたり 14〜17 回転です (`node tools/simulate-pachinko.mjs balls`)。抽選だけの出玉率は千円 16 回転で約 94%、18 回転で約 106% です (`node tools/simulate-pachinko.mjs spec 16`)。
- 液晶: 数字図柄 3 列 (左 → 右 → 中の順に停止、奇数が確変図柄)、ステップアップ予告 (最大 5 段)、擬似連 (NEXT)、リーチ (ノーマル / SP / SPSP / 全回転)、カットイン (青 → 緑 → 赤 → 金)、保留の色 (白 → 青 → 緑 → 赤 → 金 → 虹)、ラウンド表示、ST・時短の残り回数、右打ち指示。
- 筐体は実際の CR 機に寄せています: クリスタル調の光る枠 (通常は紫、ST は虹、大当たりは金の点滅)、上部の赤いドット LED ロゴ (通常 CIRCUS / ST RUSH / 大当たり FEVER)、左右上のスピーカー、台上のデータ表示機 (大当り回数・スタート・総スタート・最大連チャン・千円あたり回転数・連チャン履歴) と機種 POP、台の左のサンド、宝石型の PUSH ボタン、白く光るハンドル。
- 隣の 2 台は飾りで、玉は飛びません。暗幕をかけて目立たないようにしています。

### 手持ちの音を使う

効果音と BGM は `assets/audio/` のファイルを同じ名前で置き換えるだけで差し替わります (例: 告知の「ペカッ」は `sfx/peka.mp3`、ブイーンは `sfx/buiin.mp3`、BIG 中は `bgm/level3.mp3`)。どのファイルが何に使われているかは `src/config.js` の `assets.sfx` / `assets.bgm` を見てください。

## 抽選と制御の仕組み

1. **内部抽選** (`SlotLogic.draw`): レバー ON の時点で、設定 1〜6 の確率表 (`CONFIG.probability`) からフラグを 1 つ引きます。
   `CHERRY+BIG` のような重複当選もあります。成立したボーナスは揃うまで持ち越され、持ち越し中はボーナスを抽選し直しません。
2. **引き込み制御** (`SlotLogic.decideStop`): ボタンを押した位置から 0〜`maxSlip` コマ滑らせた候補のうち、次の優先順位で最良の 1 つを選びます。
   1. 非成立役を揃えない (蹴飛ばし)
   2. ボーナス非成立なら 7 のテンパイを避ける
   3. 成立小役を引き込む
   4. 成立ボーナスを引き込む
   5. ボーナス成立時はテンパイ形を優先する
   6. 滑りを少なくする
   残りのリールは「ランダムな押し順・タイミングで、同じ制御が働く」と仮定した期待値で評価します。
   全 9,261 出目の役判定は前計算し、フラグごとにメモ化しています。
3. 告知の抽選 (`Director.planGame`) はボーナス成立ゲームで先ペカ / 後ペカ / プレミアムを `CONFIG.notice` の比率で決め、続けて予告の有無・種類・カットインの最終色を `CONFIG.yokoku` の重みで決めます。

### 検証結果 (`node tools/simulate.mjs 600000 1.0`)

告知後に必ず 7 を揃えた場合の結果です (ボーナス中のゲームも回転数に含むため、BIG/REG の分母は仕様値より少し重く出ます)。
ボーナス確率の仕様値はアイムジャグラー EX と同じ (設定 1: BIG 1/273.1・REG 1/439.8・合算 1/168.5)。
ぶどう (実機 1/6.02・8 枚) とリプレイ (実機 1/7.3) は出すぎに感じるため、ぶどう 1/7.5・10 枚、リプレイ 1/9 に減らしました。
ボーナス中も 2 割ほどハズレのゲームが混ざります (実機はほぼ毎ゲーム揃う)。そのぶん BIG は 360 枚、REG は 112 枚まで払い出して、機械割を実機の範囲に合わせています。

| 設定 | 機械割 (シミュレーション) | 実機の公表値 |
|---|---|---|
| 1 | 約 96% | 97.0% |
| 2 | 約 96〜100% | 98.0% |
| 3 | 約 98〜99% | 99.5% |
| 4 | 約 99〜101% | 101.1% |
| 5 | 約 102〜105% | 103.3% |
| 6 | 約 103〜104% | 105.5% |

60 万ゲームを数回まわした値の幅です (1 回ごとに ±1.5% ほどぶれます)。

制御破綻・非成立テンパイはどの設定も 0 です。ぶどう・リプレイは順押しで 100% 揃います。チェリーは約 90%、ベル・ピエロは狙わないとほぼ取りこぼします (実機と同じ)。

## 磨き込みのポイント

- **確率と配当**: `CONFIG.probability` (設定ごとの分母)、`CONFIG.roles`、`CONFIG.bonus`。変更後は `node tools/simulate.mjs` で機械割を確認してください。
- **リール配列**: `CONFIG.reels.strips` (21 コマ、文字 = 図柄キー)。`simulate.mjs` の「制御破綻 0」を保ったまま変更してください。
- **告知**: `CONFIG.notice` — 先ペカ / 後ペカの比率、プレミアム率、点灯前の無音の長さ (`silenceMs`)。
- **連チャン**: `CONFIG.chain` — ゾーンの長さ、確変風の倍率 (`boost`)、スペシャル BGM の条件。
- **予告**: `CONFIG.yokoku` — 出現率 (当たり / はずれ / チェリー)、種類ごとの重み、カットイン色の重み。
- **お金**: `CONFIG.money` — 所持金、貸しメダル枚数、換金レート。
- **体感**: `CONFIG.reels.bounce` / `bounceMs` (停止時のバウンド)、`effects.shake`、`effects.vibrate` (振動パターン)、`effects.bloom`。
- **素材の差し替え**: `CONFIG.assets.*` のパスを書き換えるだけです。`symbolSkin: 'pixel'` にするとドット絵の図柄になります。
- ゲーム中に `G` キーでチューニングパネルを開くと、次ゲームのフラグ・設定・告知タイミング (先ペカ / 後ペカ)・プレミアム・予告の種類を強制して、演出だけを確認できます。

## 動作環境

- WebGL2 に対応した最新ブラウザ (Chrome / Edge / Safari / Firefox)
- 長い振動は `navigator.vibrate` に対応した端末 (主に Android Chrome) で動きます。iOS はタップ時の短い振動だけです。
