# SLOT — Three.js パチスロ実機シミュレーター

ブラウザでパチスロ実機を再現した 3D ゲームです。
抽選は「内部抽選 → 引き込み制御」の 2 段で、レバー ON の瞬間に役が決まり、ストップボタンを押したタイミングから最大 4 コマの範囲で出目が決まります。
ジャグラー型の A タイプです。液晶も物語もなく、ボーナスを引いたらリール左の告知ランプが「ペカッ」と光るだけ。
リールの上のパネルは液晶ではなく、実機と同じ「裏から照らした印刷アート」です。絵は動かず、告知中はゆっくり、ボーナス中は速く明滅するだけです。
所持金 3 万円を持って台に座り、千円ずつメダルを借りて打ち、換金して帰るまでが 1 日です。

## 起動

ES Modules と fetch を使うため、ローカル HTTP サーバー経由で開いてください (`file://` では動きません)。

```bash
cd slot
python3 -m http.server 8000      # もしくは: npx serve .
# → http://localhost:8000/
```

| URL ハッシュ | 効果 |
|---|---|
| `#debug` | 起動時にチューニングパネル (lil-gui) を開く。`G` キーや ⚙ ボタンでも開閉できる |
| `#lite` | 背景ホールと隣台を省き、ピクセル比を 1 に固定する (低スペック端末向け) |
| `#zoom` | カメラをリール寄りにする |

組み合わせるときは `#debug-lite` のようにハイフンでつなぎます。

ビルド工程も外部 CDN も使いません。依存物はすべて `assets/` に同梱しています。

## 操作

| 操作 | キーボード | マウス / タッチ (筐体を直接操作) |
|---|---|---|
| MAX BET | `B` / `Shift` | デッキ左の黄色い MAX BET ボタン (ベット待ちのあいだ光る) |
| レバー | `Space` / `Enter` / `↑` | 赤いレバー玉をタップ、または下へ引く (デッキ左側一帯が判定) |
| 停止 (左・中・右) | `←` `↓` `→` / `1` `2` `3` / `Z` `X` `C` | ストップボタン (その下の配当表あたりまで判定あり) |
| 千円入れる (46 枚) | `M` | 右の千円入れ機のボタン、または画面左上の「千円入れる」 |
| 換金して終了 | — | 画面右上の「換金」 |

iPhone は Safari の仕組み上 `navigator.vibrate` が使えないため、ios-haptics の方式で、筐体をタップした瞬間だけ本体を振動させます。
告知の「ブイーン」という長い振動は Android Chrome などの `navigator.vibrate` 対応端末で動きます。iOS では音・画面の揺れ・光で表現します。

- 自動ベットは標準でオンです。メダルが 3 枚未満になると止まるので、千円を入れてください (自動では借りません)。
- 1 ゲームは最短 4.1 秒です (実機と同じウェイト)。
- 所持金・持ちメダル・過去の戦績は localStorage に保存されます。

## お金と 1 日の流れ

| 項目 | 値 (`CONFIG.money`) |
|---|---|
| 1 日の所持金 | 30,000 円 |
| 貸しメダル | 1,000 円で 46 枚 |
| 換金 | 1 枚 20 円 (等価ではないので、出した分をそのまま流すと少し目減りする) |

台の設定 (1〜6) は日ごとに隠れて決まり (`CONFIG.settingOdds`、高設定ほど低確率)、換金したときに答え合わせとして表示されます。
換金すると、投資・換金額・収支・回転数・BIG/REG・設定と通算収支が出て、次の日に進みます。
筐体上のデータカウンターに BIG / REG / 現在の回転数 / 総回転数とスランプグラフが出るので、それを見て粘るか帰るかを決めます。

## 告知と演出

| 演出 | 意味 |
|---|---|
| 先ペカ (レバー ON で点灯) | ボーナス確定。全体の約 25% |
| 後ペカ (第 3 停止ボタンを離した瞬間に点灯) | ボーナス確定。約 75% |
| プレミアム (虹色に点滅) | ボーナス確定。告知の 1/8 |

点灯の直前に一瞬だけ音が消え、ランプが光ると同時に「ペカッ」、続けて低い「ブイーン」と振動、光の波紋が筐体に広がります。
目押しアシスト (`CONFIG.play.assistAlignAfterNotice`) がオンなら、告知後のゲームで 7 が自動で揃います。
BIG は 312 枚超、REG は 104 枚超の払い出しで終了します。

## 抽選と制御の仕組み

1. **内部抽選** (`SlotLogic.draw`): レバー ON の時点で、設定 1〜6 の確率表 (`CONFIG.probability`) からフラグを 1 つ引きます。
   `CHERRY+BIG` のような重複当選もあります。成立したボーナスは揃うまで持ち越され、持ち越し中はボーナスを抽選し直しません。
2. **引き込み制御** (`SlotLogic.decideStop`): ボタンを押した位置から 0〜`maxSlip` コマ滑らせた候補のうち、次の優先順位で最良の 1 つを選びます。
   1. 非成立役を揃えない (蹴飛ばし)
   2. ボーナス非成立なら 7 のテンパイを避ける
   3. 成立小役を引き込む
   4. 成立ボーナスを引き込む
   5. ボーナス成立時はテンパイ形を優先する
   6. 滑りを少なくする
   残りのリールは「ランダムな押し順・タイミングで、同じ制御が働く」と仮定した期待値で評価します。
   全 9,261 出目の役判定は前計算し、フラグごとにメモ化しています。
3. 告知の抽選 (`Director.planGame`) はボーナス成立ゲームで先ペカ / 後ペカ / プレミアムを `CONFIG.notice` の比率で決めます。

### 検証結果 (`node tools/simulate.mjs 100000 0.97`)

告知後に 97% の確率で 7 を目押しし、それ以外はランダムに押した場合の結果です (ボーナス中のゲームも回転数に含むため、BIG/REG の分母は仕様値より少し重く出ます)。

| 設定 | 機械割 | BIG | REG | 制御破綻 | 非成立テンパイ |
|---|---|---|---|---|---|
| 1 | 約 98% | 1/290 | 1/485 | 0 | 0 |
| 3 | 約 100% | 1/289 | 1/382 | 0 | 0 |
| 6 | 約 104% | 1/297 | 1/288 | 0 | 0 |

ぶどう・リプレイは順押しで 100% 揃います。チェリーは約 90%、ベル・ピエロは狙わないとほぼ取りこぼします (実機と同じ)。

## 磨き込みのポイント

- **確率と配当**: `CONFIG.probability` (設定ごとの分母)、`CONFIG.roles`、`CONFIG.bonus`。変更後は `node tools/simulate.mjs` で機械割を確認してください。
- **リール配列**: `CONFIG.reels.strips` (21 コマ、文字 = 図柄キー)。`simulate.mjs` の「制御破綻 0」を保ったまま変更してください。
- **告知**: `CONFIG.notice` — 先ペカ / 後ペカの比率、プレミアム率、点灯前の無音の長さ (`silenceMs`)。
- **お金**: `CONFIG.money` — 所持金、貸しメダル枚数、換金レート。
- **体感**: `CONFIG.reels.bounce` / `bounceMs` (停止時のバウンド)、`effects.shake`、`effects.vibrate` (振動パターン)、`effects.bloom`。
- **素材の差し替え**: `CONFIG.assets.*` のパスを書き換えるだけです。`symbolSkin: 'pixel'` にするとドット絵の図柄になります。
- ゲーム中に `G` キーでチューニングパネルを開くと、次ゲームのフラグ・設定・告知タイミング (先ペカ / 後ペカ)・プレミアムを強制して、演出だけを確認できます。

## 動作環境

- WebGL2 に対応した最新ブラウザ (Chrome / Edge / Safari / Firefox)
- 長い振動は `navigator.vibrate` に対応した端末 (主に Android Chrome) で動きます。iOS はタップ時の短い振動だけです。
