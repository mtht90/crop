# ルーン・レーンズ（Rune Lanes）

スマホ縦画面向けの「タワーディフェンス × デッキ循環型カードバトル」です（CPU 対戦のみ、MVP 版）。
Phaser 4 + TypeScript + Vite で作っています。

- 左右 2 レーン、守護塔 ×2 と王の塔 ×1 を壊し合う
- カードは **山札 → 手札 → 捨て札 →（シャッフル）→ 山札** と循環する
- マナが足りていれば、手札のどのカードもいつでも使える
- サポートカードは **味方ユニットへドラッグ** して強化・回復をかける

このフォルダはリポジトリ内で独立しています（親フォルダの Minecraft プラグインのビルドとは無関係です）。

## 起動方法

```bash
cd rune-lanes
npm install
npm run dev       # 開発サーバー（表示された URL をスマホ/PC のブラウザで開く）
npm run build     # 型チェック後、dist/ に静的ファイルを出力
npm run preview   # ビルド結果の確認
npm test          # ロジックのユニットテスト（Vitest）
```

`dist/` は相対パスで出力されるので、任意の静的ホスティング（GitHub Pages など）のサブディレクトリにそのまま置いても動きます。

## 操作方法

| 操作 | 内容 |
|---|---|
| ユニット・建物カード | 手札からアリーナへドラッグ。ゴーストと攻撃範囲が表示され、置けない場所は赤く塗られる |
| 呪文カード（火球） | アリーナの任意の地点へドラッグ。効果範囲の円が表示される |
| サポートカード | 場の味方ユニットへドラッグ。対象にできる味方が光り、指を重ねた味方が金色で強調される。味方以外の場所で離すとキャンセル（マナもカードも戻る） |
| 捨て札 | 右下の捨て札をタップすると中身を一覧表示 |
| 山札 | 左下に残り枚数とドローまでのゲージ。手札が上限（6 枚）だとゲージが止まり「上限」と表示される |

マナが足りないカードは暗く表示され「あと N」と不足量が出ます。
相手の守護塔を壊したレーンは、川を越えて相手陣地の手前 6 タイルまで配置できるようになります。

## フォルダ構成

```
src/
  main.ts
  core/        型定義・シード付き乱数
  data/        cards.json / decks.json / balance.json / assets-manifest.json
  entities/    Combatant（ユニット・建物・塔の共通データ）, Unit, Tower, Projectile
  systems/     DeckSystem, ManaSystem, BuffSystem, Targeting, Movement, Combat, MatchTimer, Arena, BattleWorld
  ai/          CpuController と思考ルール（rules.ts）
  ui/          手札・山札・捨て札・マナバー・HUD・カード・ユニット表示
  scenes/      Boot, Title, Battle, Result, Credits, DeckView
tests/         Vitest（Phaser に依存しないロジックのテスト）
public/assets/ 素材（sprites, tiles, ui, effects, audio/bgm, audio/se, fonts）
scripts/       gen-assets-md.py（マニフェストから ASSETS.md を生成）
```

`systems/` 以下はすべて Phaser 非依存の純粋な TypeScript です。`BattleWorld.update(dt)` を固定タイムステップ（30Hz）で呼び出し、描画側（`BattleScene`）は状態とイベントを読むだけなので、描画のフレームレートで結果が変わりません。

## 素材の差し替え方

1. `src/data/assets-manifest.json` に「ゲーム内キー → ファイルパス」の対応がまとまっています。
2. 同じパスにファイルを上書きするか、`path` を書き換えるだけで差し替わります（コード変更は不要）。
3. 画像が読み込めなかった場合は、自動で色付きの四角いプレースホルダーになり、ゲームは動き続けます（コンソールに一覧が出ます）。ファイルを置けば次回から自動で本物に変わります。
4. ユニットの見た目の大きさは `cards.json` の `displayScale` で調整します（16px 素材 × 倍率）。
5. 追加・変更したら `python3 scripts/gen-assets-md.py > ASSETS.md` で記録表を更新してください。クレジット画面は manifest の `sources` から自動生成されます。
6. ライセンス表記のない素材（B 区分）を使う場合は、`sources` の `category` を `"B"`、`license` を `"unspecified"` にしてください。クレジット画面にも「ライセンス未記載」と出ます。

素材の入手元とライセンスは [ASSETS.md](ASSETS.md)、手動入手が必要な素材は [ASSETS_TODO.md](ASSETS_TODO.md) を参照してください（現在は手動入手が必要な素材はありません）。

## 数値の調整

- `src/data/balance.json`：マナ（最大・初期・回復秒数・倍率）、デッキ（初期手札 4 / 上限 6 / ドロー間隔 4 秒）、試合時間、バフの重ねがけルール（`refresh` か `stack`）、呪文の塔へのダメージ倍率、塔の性能、CPU の難易度パラメータ
- `src/data/cards.json`：各カードの数値（HP・攻撃力・射程・速度・体数・範囲・寿命・サポート効果など）
- `src/data/decks.json`：プレイヤーと CPU のデッキ（同じカード ID を複数書けば複数枚入る）

## 設計メモ（仕様に書かれていなかった点の判断）

- **エンジン**：Phaser の最新安定版 4.2.1 を使用。Phaser 3 との差分（ティントモード、DynamicTexture の `render()` など）に合わせています。
- **配置場所**：既存リポジトリ（Minecraft プラグイン）とビルドを分けるため、`rune-lanes/` サブディレクトリに置きました。
- **画面レイアウト**：論理解像度 720×1280。アリーナは 1 タイル 32px（18×32 タイル＝576×1024px）で、左右の 72px は森の装飾と情報表示（CPU の手札枚数・撃破数・残り時間）に使っています。下部 234px が手札エリアです。
- **呪文の塔へのダメージ**：火球は塔に 35%（`spell.towerDamageRatio`）しか効かないようにしました。王の塔を呪文だけで削り切る展開を防ぐためです。
- **王の塔の起動**：呪文を含め、王の塔が 1 でもダメージを受けたら起動します。
- **防衛砲台**：寿命 30 秒で消えます（HP の自然減少はなし）。残り寿命は HP バーの下の黄色いバーで表示します。
- **配置範囲の拡張**：相手の守護塔を壊したレーン（左右半分）で、川の向こう 6 タイルまで配置可能（`EXTENDED_DEPLOY_DEPTH`）。川の上には置けません。
- **延長戦**：時間切れで撃破数が同数なら 1:00 の延長戦に入り、延長中に撃破数で差がついた瞬間に決着します。延長後も同数なら塔の残り HP の合計割合で判定し、それも完全に同じなら引き分けです。
- **残り 1 分の BGM**：別曲（Junkala「Level 3」）に切り替えます。
- **出現待機**：配置後 1 秒は半透明で点滅し、無敵で行動しません（塔やユニットの標的にもなりません）。
- **ユニットの標的**：攻撃中の相手が射程内にいる間はロックし、外れたら視界内の最も近い敵を探し直します。いなければ自分のレーンの守護塔（壊れていれば王の塔）へ橋を経由して進みます。
- **サポートの対象**：味方の「ユニット」のみ（建物・塔には使えません）。群れユニットには、指を重ねた 1 体だけに効きます。
- **CPU の思考**：`src/ai/rules.ts` に「迎撃」「サポート」「呪文」「攻撃」「回転（手札上限時）」の 5 ルールがあり、それぞれがスコア付きの候補を出し、最高スコアを採用します。ルールは配列に関数を足すだけで追加できます。「やさしい」は思考間隔が長く、実行までの遅延と判断のランダム性が大きく、ときどき行動を見送ります。CPU もプレイヤーと同じ `BattleWorld.playCard` を通すので、カードのルールは完全に同じです。
- **DeckEdit（デッキ編集）**：任意項目のため今回は未実装です。代わりにタイトルの「デッキ確認」で 12 枚の性能を見られます。`BattleScene` は `deck` 引数を受け取れるようにしてあるので、編集画面は後から追加できます。

### ドロー周りのテンポについての提案

試遊用のたたき台は「初期手札 4 / 上限 6 / ドロー 4 秒」です。マナ回復は 2.8 秒で 1 なので、平均コスト 3.25 のこのデッキでは **1 枚使うのに約 9.1 秒分のマナが必要**です。一方ドローは 4 秒ごとなので、手札はすぐ上限に達してドローが止まりがちです（＝実質的に「上限 6 枚の手札から自由に選ぶ」ゲームになる）。

| 案 | 設定 | ねらい |
|---|---|---|
| A（現状） | 4 / 6 / 4秒 | 手札に余裕があり、初心者でも詰まりにくい |
| B（循環を意識させる） | 初期 3 / 上限 5 / ドロー 6 秒 | 山札・捨て札の循環を体感しやすく、引きの読み合いが生まれる |
| C（残り1分でテンポアップ） | B ＋ マナ2倍の間はドロー 3 秒 | 終盤の盛り上がりに合わせてカードも速く回る（要実装：`DeckSystem.config.drawInterval` を試合時間に応じて変更） |

実機での試遊後は、まず B を試すことをおすすめします（`balance.json` の `deck` を書き換えるだけで変更できます）。
